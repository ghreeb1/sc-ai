mb-6 h-[0.05rem] border-0 bg-palette-gray6"/><p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">This guide explains how to use Environment Variables in Expo Application Services (EAS): Build, Updates, Workflows, and Hosting. For general information on how environment variables work with the Expo framework, refer to <a class="cursor-pointer decoration-0 hocus:opacity-80 font-normal text-link visited:text-link hocus:underline [&amp;_code]:hocus:underline [&amp;_b]:text-link [&amp;_code]:text-link [&amp;_em]:text-link [&amp;_i]:text-link [&amp;_span]:text-link [&amp;_strong]:text-link" href="/guides/environment-variables">Environment variables in Expo</a>.</p>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">During local development, environment variables are loaded from your local <span class="leading-[1.6154] text-inherit font-semibold" data-text="true">.env</span> or <span class="leading-[1.6154] text-inherit font-semibold" data-text="true">.env.local</span> files. These files are generally excluded from the project&#x27;s version control (that is, if they are listed in the <span class="leading-[1.6154] text-inherit font-semibold" data-text="true">.gitignore</span> file or not committed) so they are not available for jobs that run on a remote server, for example, EAS Build and EAS Workflows. Additionally, most projects have multiple app variants and require multiple sets of environment variables (for instance Development and Production).</p>
<h2 class="text-inherit text-[25px] leading-[1.4] font-bold tracking-[-0.021rem] mt-8 mb-3.5 [&amp;_code]:text-[90%] max-md:text-[22px] max-md:leading-[1.409] max-sm:text-[19px] max-sm:leading-[1.5263] group flex gap-1 scroll-m-5" data-heading="true" id="why-use-eas-environment-variables">Why use EAS environment variables<a href="#why-use-eas-environment-variables" class="border border-solid rounded-full font-medium items-center whitespace-nowrap gap-2 text-sm border-button-quaternary bg-button-quaternary text-button-quaternary shadow-none hocus:bg-button-quaternary-hover active:scale-98 relative my-auto inline-flex size-6.25 min-w-6.25 justify-center p-0 transition-all duration-default invisible opacity-0 group-hover:visible group-hover:opacity-100 group-focus-visible:visible group-focus-visible:opacity-100"><span class="flex self-center text-inherit leading-none select-none"><svg aria-label="permalink" class="icon-sm shrink-0" width="24" height="24" viewBox="0 0 24 24" fill="none" xmlns="http://www.w3.org/2000/svg"><path d="M10 13a5 5 0 007.54.54l3-3a5 5 0 00-7.07-7.07l-1.72 1.71" stroke="#9B9B9B" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"></path><path d="M14 11a5 5 0 00-7.54-.54l-3 3a5 5 0 007.07 7.07l1.71-1.71" stroke="#9B9B9B" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"></path></svg></span></a></h2>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">You might want to use EAS Environment variables if you need to:</p>
<ul class="leading-[1.6154] text-inherit list-disc ml-6 [&amp;_ol]:mt-2 [&amp;_ol]:mb-4 [&amp;_ul]:mt-2 [&amp;_ul]:mb-4 mb-[1.5ch] pl-[1ch]">
<li class="text-inherit text-base leading-relaxed font-normal mb-2" data-text="true">Keep configuration in one place for cloud builds, updates, and workflows without committing <span class="leading-[1.6154] text-inherit font-semibold" data-text="true">.env</span> files.</li>
<li class="text-inherit text-base leading-relaxed font-normal mb-2" data-text="true">Separate values by environment (<code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">development</code>, <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">preview</code>, <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">production</code>) while reusing names.</li>
<li class="text-inherit text-base leading-relaxed font-normal mb-2" data-text="true">Control visibility (plain text, sensitive, secret) so only the right surfaces can read each value.</li>
<li class="text-inherit text-base leading-relaxed font-normal mb-2" data-text="true">Apply the same set locally with <a class="cursor-pointer decoration-0 hocus:opacity-80 font-normal text-link visited:text-link hocus:underline [&amp;_code]:hocus:underline [&amp;_b]:text-link [&amp;_code]:text-link [&amp;_em]:text-link [&amp;_i]:text-link [&amp;_span]:text-link [&amp;_strong]:text-link" href="/eas/environment-variables/manage#pull-variables-for-local-development"><code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">eas env:pull</code></a> or inside CI/CD.</li>
</ul>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">These are the problems that EAS Environment variables are built to solve. With EAS Environment variables, the variables are configured in EAS via the EAS CLI or directly on the <a target="_blank" rel="noopener noreferrer" class="cursor-pointer decoration-0 hocus:opacity-80 font-normal text-link visited:text-link hocus:underline [&amp;_code]:hocus:underline [&amp;_b]:text-link [&amp;_code]:text-link [&amp;_em]:text-link [&amp;_i]:text-link [&amp;_span]:text-link [&amp;_strong]:text-link" href="https://expo.dev">expo.dev</a> dashboard, and can be accessed by EAS Build and EAS Workflows as well as your local machine via the EAS CLI.</p>

<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">By default, EAS supports three environments for environment variables: <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">development</code>, <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">preview</code>, and <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">production</code> environments. Custom environment names are available on Enterprise and Production plans.</p>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">Each environment is an independent set of variables that can be used to customize your app in different contexts. For example, you can use different API keys for development and production, or use different bundle identifiers for app store releases.</p>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">Every EAS Build and Workflows job runs using environment variables from one of the available environments. You can also use environments for updates, allowing you to use the same set of environment variables for your build jobs. When publishing an update, specify the environment with the required <code class="text-inherit text-xs leading-[130%] font-normal inline-block rounded-md border border-secondary bg-subtle px-1 py-0.5" data-text="true">--environment</code> flag.</p>
<p class="text-inherit font-normal text-base [&amp;_strong]:wrap-break-word mb-[1.5ch]" data-text="true">Environment variables can be assigned to multiple environments and have the same value across all of them, or be created for a single environment.</p>
